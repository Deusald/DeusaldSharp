DeusaldSharp 11.1.0 splits the Unity package into one package per module and signs every Unity package. It contains
no library changes compared to 11.0.3.

## Unity packages

- **One package per module** - every module is its own Unity package with its own dll, named
  `com.deusald.deusaldsharp.<module>` (`com.deusald.deusaldsharp.core`, `.vectors`, `.splines`, `.clock`,
  `.coroutines`, `.messages`, `.injector`, `.glicko`, `.proto`). Install only the modules you use.
- `com.deusald.deusaldsharp` is now a meta-package with no code of its own that installs every module.
- **Signed packages** - every Unity package is signed by Deusald and attached to the GitHub Release as
  `<package-name>-<version>.tgz`. OpenUPM publishes these signed tarballs, so the Package Manager shows the packages as
  signed (Unity 6.3+).
- The dlls keep their GUIDs, so references in your project are not affected.

## Upgrading (Unity)

- **OpenUPM**: no changes needed - `com.deusald.deusaldsharp` now pulls in every module package. To use only some
  modules, replace it with the module packages you need.
- **Git URL**: the `UnityPackage.NetStandard2.1` folder no longer exists. Replace the old URL with one URL per module,
  from `?path=/UnityPackages/com.deusald.deusaldsharp.<module>`. Unity does not resolve git dependencies, so add the
  modules each module depends on too (for example `core` and `vectors` for `splines`).

See [Installation](https://github.com/Deusald/DeusaldSharp#unity) for details.

## Release pipeline

- The release workflow signs every Unity package with the UPM CLI, in parallel, and attaches the signed tarballs to the
  same GitHub Release as the NuGet packages. Nothing is published unless every package is signed and every test passes.
