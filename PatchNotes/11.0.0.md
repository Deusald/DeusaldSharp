DeusaldSharp 11.0.0 splits the library into separate module packages, hardens all binary decoding against malicious
input and fixes a long list of bugs. Several fixes change behavior or the binary format - read **Breaking changes**
before upgrading.

## Highlights

- **Module packages** - every module is its own NuGet package and dll (`DeusaldSharp.Core`, `.Vectors`, `.Splines`,
  `.Clock`, `.CoRoutines`, `.Messages`, `.Injector`, `.Glicko`, `.Proto`). `DeusaldSharp` is now a meta-package that
  references all of them, and everything stays in the `DeusaldSharp` namespace - no code changes needed.
- **Proto source generator bundled** in `DeusaldSharp.Proto` - no separate analyzer package to install.
- **Safe on untrusted data** - Proto messages and all `BinaryReader` list/array readers validate lengths before
  allocating and limit nesting depth. Malformed or malicious payloads throw `InvalidDataException` instead of hanging a
  thread, allocating gigabytes or crashing the process.
- **New `Forget()`** - fire-and-forget tasks never crash the process; exceptions go to a per-call handler or the global
  `TaskExtensions.UnhandledException`.
- **Correct Glicko-2** ratings and a redesigned inactivity decay.
- **Packages on GitHub Packages** in addition to NuGet.org, and GitHub Releases with patch notes.

## Security

- Proto: a negative field length caused an infinite loop (one 6-byte packet pinned a server thread forever).
- Proto: unbounded nesting caused an uncatchable `StackOverflowException`; depth is now limited by
  `ProtoMsgBase.MaxDepth` (default 64).
- Proto and `BinaryReader` extensions: attacker-controlled lengths and counts allocated memory before validation
  (a 4-byte packet allocated 2 GB).
- All decoding failures are reported as `InvalidDataException` with the cause as `InnerException`.

## Proto

- Fixed: two messages with the same name in different namespaces, or a message split across several `partial` files,
  made the generator emit nothing at all (the CS8785 warning).
- Fixed: fields of base messages were not serialized by derived messages.
- Added support for nested message types, `internal` messages, keyword field names (`@class`), `string?` / `Version?`
  fields, arrays and `[field: ProtoField]` on auto-properties.
- Deserializing into a reused instance resets fields that are missing from the payload.
- Generated code uses fully qualified names, so user types named `List`, `Encoding` etc. no longer break it.
- New diagnostics: DSHP008 (readonly field), DSHP009 (static / const field), DSHP010 (ID already used by a base message),
  DSHP011 (private base field), DSHP012 (containing type not partial).
- The generator pipeline is now incremental, which makes IDE builds faster.

## Core

- `Forget()` no longer crashes server processes when the task faults.
- `ComputeHmacSha256Hex` encoded text as ASCII, so different non-ASCII inputs produced the same MAC; it now uses UTF-8.
- `TimeSpan` serialization is exact (int64 ticks) and `Version` keeps all four components.
- Serializable enums: unsigned values are no longer sign-extended.
- `Shuffle` is unbiased and can no longer use a negative index.
- `HexStringToByteArray` throws `FormatException` on invalid input; `ReadGuid` throws `EndOfStreamException` on short data.
- Zip entries use `/` separators, keep empty directories and skip symlinks.
- Culture-invariant casing and argument parsing (`ToSnakeCase`, `FirstToUpper`, `TakeSimpleType`, ...).
- `MathMod` overflow, `IsOdd` for negative numbers, `InverseLerp(a, a, x)`, `NumberOfSetBits` and `IsSingleBitOn` for
  negative values fixed.
- Float comparisons (`AreFloatsEquals`, `IsFloatZero`, vector `==`) use a real tolerance: `MathUtils.EPSILON` = 1e-6.
- `FlagsMemory` validates bit indexes.
- `UsernameVerificator` accepted names with a trailing newline (`"admin\n"`) - the regex is now anchored correctly,
  `null` returns `false`, and `CleanUsername` can no longer return a name ending with a space.

## Vectors & Splines

- `TVector3<T>.Equals` / `GetHashCode` ignored `z` - `(1, 2, 3)` and `(1, 2, 4)` were the same dictionary key.
- `Vector2/3.Normalize` works for very small and very large vectors; `IsValid` rejects NaN and infinity.
- `Vector2.Reflect(normal)` returns `Vector2` instead of `Vector3`.
- `Spline2D`: stale distance cache after changing points, stale data after removing points, and crashes for empty /
  single-point splines, negative `t` and invalid sample counts fixed. Open splines clamp `t`, closed splines wrap it.

## Clock

- `GameServerClock` ticks at the exact rate (60 Hz ran at 62.5 Hz).
- After a long tick both clocks skip missed frames instead of firing them back-to-back.
- New `TickException` event: with a subscriber, tick exceptions are reported and the clock keeps ticking.
- `Kill()` waits for the running tick, both clocks are `IDisposable`, and shutdown is thread-safe.

## CoRoutines

- Finished coroutines leaked their controller subscriptions.
- Killing a coroutine from inside itself (or via its tag) didn't stop it.
- Killed coroutines run their `finally` / `using` blocks.
- Repeated `WaitForSeconds` no longer drift (~15% at 60 fps).
- An exception in a coroutine kills only that coroutine and propagates to the caller of `Update`.
- `GetCurrentCoHandle()` returns the right handle in a nested coroutine's first step; `Reset()` kills all coroutines.

## Messages

- Sent messages were returned to the wrong pool, so pooling never reused messages and memory grew with every `Send`.
- An exception in a receiver left the bus stuck - no message was delivered afterwards.
- Messages with get-only properties couldn't be sent; fields are now reset between uses.
- `Clear()` inside a receiver, `Consume()` outside a dispatch and private slots in base classes fixed.

## Injector

- Private `[Inject]` members declared in base classes are injected.

## Glicko

- The 1v1 `Update` and `GetWinProbability` used a wrong g(φ) formula: ratings moved about half as fast as they should
  and win probabilities were squeezed towards 50%. The 1v1 `Update` now uses the same code path as the list `Update`,
  and `GetWinProbability` takes both players' deviations into account.
- `DecayPlayer` has a new deterministic signature: one rating period per elapsed period after the deadline, no hidden
  grace days, and a returned `nextDecayDeadline` so partially elapsed periods are not lost.

## Breaking changes

**Packaging**
- Remove the old `DeusaldSharp.Analyzers` package reference - otherwise the Proto generator runs twice.
- The Unity package contains one dll per module instead of a single `DeusaldSharp.dll`.

**Binary format** - upgrade clients and servers together and re-create stored data written by 10.x:
- `TimeSpan`: int64 ticks (was a `double` of milliseconds).
- `Version`: four int32 components, 16 bytes (was 12).
- Unsigned serializable enums with the top bit set are written with their real value.
- `ComputeHmacSha256Hex` results change for non-ASCII input.

**API & behavior**
- `Glicko.DecayPlayer(player, decayDeadline, now, period, out long periodsApplied, out DateTime nextDecayDeadline)`
  replaces the old overload; 1v1 `Update` and `GetWinProbability` return different (correct) values.
- `Clamp` throws `ArgumentException` when `min > max`.
- `FlagsMemory` methods throw `ArgumentOutOfRangeException` for out-of-range indexes.
- Exceptions thrown by message receivers and coroutines propagate to the caller (`Send` / `Update`).
- Proto: malformed data throws `InvalidDataException`; messages nested deeper than 64 levels are rejected.
- `Vector2.Reflect(normal)` returns `Vector2` - recompile code built against 10.x.
